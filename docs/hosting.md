# Исследование и сравнение размещения PostgreSQL

Дата проверки: **17.11.2026**. Цель — выбрать площадку для постоянной учебной
таблицы и независимого ограниченного CRUD преподавателя. Сравниваются три
альтернативы, включая отечественную и бесплатную; отдельно обоснован личный сервер.
Платные услуги не приобретались. Секреты в отчёт не включены.

## Личная проверка Helios

Использовались только команды чтения и временное локальное перенаправление
порта. Туннель закрыт. Пароли и файлы учётных данных в проект не копировались.

| Проверка | Наблюдаемый результат |
|---|---|
| SELECT version() | PostgreSQL 18.3, сборка для FreeBSD |
| current_database() | Общая учебная БД studs |
| max_connections | 512 — общий лимит, не гарантированная квота студента |
| Текущая роль в pg_roles | rolsuper=false, rolcreaterole=false, rolcreatedb=false, rolconnlimit=-1 |
| Права БД | CONNECT=true, CREATE=false, TEMPORARY=true |
| Права схем | Личная: USAGE/CREATE=true; public: CREATE=false |
| search_path | Личная схема, затем public |
| statement_timeout / idle_in_transaction_session_timeout | 0 на момент проверки; административные ограничения этим не исключаются |
| Размер studs | Около 2357 МБ всей общей БД, не личная квота |
| ZFS userquota | 1073741824 байта = 1 ГиБ для домашнего каталога; не относится к диску PostgreSQL |
| Node.js/npm | Не найдены в PATH сеанса; возможность отдельной установки не исключена |
| SSH forwarding до pg:5432 | pg_isready отвечает accepting connections; SQL-аутентификация именно через туннель не проверялась |

Для приложения на другой машине транспорт через SSH доступен из проверенной
сети. Постоянный туннель с личного сервера и работа Node.js с Helios не проверялись.
Таблицу можно создать в личной схеме. Для **новой** отдельной роли нужен
администратор; возможный GRANT существующей отдельной роли преподавателя требует
выяснения её наличия и согласования. Основной пароль Helios передавать нельзя.
Точную квоту PostgreSQL требуется уточнять у факультета: домашний лимит и размер
общей БД не заменяют её.

## Обоснование выбора личного сервера

Выбран **личный сервер с PostgreSQL 17**, Node.js/Express и Caddy. 22.11.2026
Ubuntu-сервер доступен по SSH; приложение и база запущены, API↔SQL CRUD проверен.
Домен triadmind.ru указывает на сервер. Caddy получил сертификат Let's Encrypt;
внешняя проверка HTTPS вернула 200 и действительный сертификат.
Стоимость определяется будущим договором; бесплатность сервера не предполагается.

Решающий критерий — самостоятельное выделение tasks_app и tasks_reviewer с CRUD
только учебной таблицы. Минимум Timeweb с одним пользователем этого не обеспечивает
без другой конфигурации/согласования. Supabase Free достаточен по размеру, но
требует проверки аккаунта/сети и учёта возможной паузы. Helios доступен, однако
выдача нового логина ограничена. На личном сервере роли воспроизводятся
подготовленным provisioning-скриптом.

Таблица tasks находится в отдельной tasks_db и постоянном Docker volume. Пул
приложения ограничен пятью соединениями. PostgreSQL открыт только на loopback;
преподаватель подключается согласованным ограниченным SSH-туннелем. На сервере
проверены две роли, обмен API↔SQL и сохранение после перезапуска приложения.
Публичный HTTPS подтверждён; независимое подключение преподавателя извне ещё
требует настройки и проверки по [инструкции](deployment.md).
