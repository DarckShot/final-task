# Список дел: Express и PostgreSQL

Автор: Краснопольский Сергей Вячеславович, логин Moodle `sergey_krasn`.
Приложение предназначено для итоговой работы от 24.10.2026. Пользователь вводит
токен, видит сведения автора, создаёт дела, меняет названия, отмечает выполнение
и удаляет записи. Поле группы позволяет просматривать отдельный запуск проверки.
Кнопка «Добавить итоговую работу» создаёт требуемое персональное дело в группе
`manual` по явному действию пользователя. Автоматическое заполнение базы при
старте намеренно отсутствует: ручное создание остаётся наблюдаемым действием.

Выбран личный сервер с PostgreSQL и Caddy. Это позволяет управлять сроком
доступности, сертификатом HTTPS и отдельными ограниченными учётными записями.
База хранится в постоянном Docker volume. Публичное развёртывание владелец
выполняет самостоятельно; рабочий HTTPS-адрес следует добавить после проверки.
Наличие работающего приложения в интернете пока не заявляется. Анализ альтернатив
приведён ниже; подробности сетевой проверки доступны в [анализе размещения](docs/hosting.md).

Код разделён на HTTP-маршруты, проверку входных данных, запросы PostgreSQL и
небольшой браузерный интерфейс. Фреймворк фронтенда для такого объёма не требуется.
Параметризованные SQL-запросы исключают подстановку пользовательских строк в SQL.
Каждый запрос читает актуальное состояние таблицы; серверного списка в памяти нет.
Индекс по автору, группе и времени ускоряет выборку и обеспечивает устойчивый порядок.

Все маршруты API требуют Bearer-токен, включая сведения автора. Исключение —
публичный `/login/`, возвращающий только логин обычным текстом. Токен вводится
пользователем и живёт в памяти вкладки; обновление страницы завершает сеанс.
Автор, UUID, начальный статус и время создания определяются сервером. Проверяются
типы, допустимые поля, длина названия, формат группы и идентификатора. Ошибки
возвращаются JSON-объектом; недоступность базы означает HTTP 503. Пользовательские
названия выводятся текстом, поэтому HTML внутри названия не исполняется.

Учебная таблица `tasks` находится в отдельной базе `tasks_db`. Приложение и
преподаватель используют разные роли с правами чтения, добавления, изменения и
удаления только этой таблицы. Административные реквизиты нужны исключительно для
инициализации. Для преподавателя предусмотрен ограниченный SSH-туннель: способ
доступа необходимо согласовать заранее. Порт PostgreSQL опубликован только на
loopback сервера. Пароли, рабочие токены и строки подключения исключены из Git.

Локально проверено на Node.js 22.17.1, PostgreSQL 14.19 и PostgreSQL 17 в Docker;
серверная конфигурация использует PostgreSQL 17. Точные зависимости фиксирует lock-файл. Команды ниже
устанавливают зависимости, создают схему и запускают приложение после заполнения
конфигурации. Отдельные тесты проверяют валидацию, настоящий HTTP/SQL CRUD,
обновления из независимого SQL-соединения, сохранение после перезапуска и права
ролей. Браузерная проверка охватывает вход, все операции и мобильную ширину.
Полная инструкция находится в [развёртывании](docs/deployment.md), а подтверждённые
результаты и оставшиеся действия — в [проверке задания](docs/verification.md).

```sh
npm ci
cp .env.example .env
# Заполните конфигурацию и создайте отдельную tasks_db в PostgreSQL.
npm run db:init
npm run db:roles
# DATABASE_URL должен использовать созданную роль tasks_app.
npm start
```

```sh
npm test
# TEST_DATABASE_URL — отдельная одноразовая тестовая БД с администратором.
npm run test:integration
npm run test:roles
npm run test:ui
```
